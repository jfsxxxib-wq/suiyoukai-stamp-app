# 先生ページ・管理者対局名簿 本番候補 実装記録

作成日: 2026-09-01
状態: ローカル実装・自動試験完了／未公開／main未反映／本番データ未接続

## 基準にした承認

- 先生ページ・管理者名簿の見本: 悦子さん「これで大丈夫です」
- 基本の手合いと逆コミを別に保存する方式: 悦子さん「この方法でお願いします」
- 逆コミは黒が受け取る仕様で固定
- 参加者本人への表示同意確認は置かない
- アプリを使わない参加者を管理者が追加し、記入漏れを訂正できる
- 対局情報に勝敗を含める

## 実装場所

`prototype/teacher-admin-production-candidate/`

既存の非公開Sites試験サイトとは別の作業用コピーである。`.openai/hosting.json` には `project_id` がなく、公開先と結び付いていない。既存の `prototype/reception-entrance-sites-private` の `main` は変更していない。

## 実装した内容

### 管理者ページ `/admin`

- 日付別の対局名簿
- アプリを使わない参加者の追加
- 名前、棋力、先生、時刻、基本の手合い、逆コミ、勝敗の訂正
- 同じ日・同じ名前・同じ先生の重複防止
- 他の画面で先に訂正された場合の上書き防止（version）
- 管理者入力とアプリ受付の表示区別
- 記入待ち件数の表示
- 作成・訂正の変更履歴保存

### 先生ページ `/teacher`

- 先生本人の担当対局だけを日付別に表示
- 名前、棋力、基本の手合い、逆コミ、勝敗を表示
- 画面やURLから先生を選ばせない
- 先生IDはログイン利用者とサーバー設定の対応表から決定
- 別の先生の対局は取得APIの応答へ含めない

### 対局データ

- 基本の手合い: `sen` または `stones` と置き石数 2〜9
- 逆コミ: 半目単位の整数で保存。3目は `6`、6目半は `13`
- 逆コミ受取人: `black` で固定
- 勝敗: `participant_win`、`participant_loss`、`jigo`
- 表示: 「2子局・逆コミ3目」「先・逆コミ6目半」などへ変換
- 削除機能は今回の範囲に含めていない

## 認証・権限

本番候補は `oai-authenticated-user-id` をサーバー側で確認する。

- `SUIYOUKAI_ADMIN_USER_IDS`: 管理者の利用者IDをカンマ区切りで設定
- `SUIYOUKAI_TEACHER_USER_MAP`: 利用者IDと先生IDのJSON対応表
- `SUIYOUKAI_LOCAL_TEST_MODE=1`: ローカルの架空データ試験だけで使用

ローカル試験用ヘッダーは、`SUIYOUKAI_LOCAL_TEST_MODE=1` のとき以外は権限として受け付けない。本番ではこの変数を設定しない。

本番の管理者ID、先生ID、D1データはまだ設定・接続していない。

## データベース

- `teachers`: 先生マスター
- `match_records`: 対局記録
- `match_record_audit`: 作成・訂正履歴
- 先生・日付・時刻の索引
- 日付・時刻の管理者名簿用索引
- 置き石、逆コミ、手合い組合せのDB制約
- アプリ側の外部受付IDを将来重複させない一意索引

## 承認・権限について

外した方がよい承認や権限はない。公開、main、GitHub、本番データ、本番QRの承認は残す。Codexによる実画面の自動確認を行う場合だけ、`127.0.0.1` のローカル画面へのアクセスをその確認時に限って許可すればよい。OSやブラウザ全体の保護を弱める必要はない。
