## 1. この文書の位置づけ

この文書は、承認済みの実装前仕様書Ver.1を、実装後に安全に確認するための試験項目へ展開したものである。

この文書の作成時点では、次の作業を行わない。

- 通常アプリ本体の変更
- Google Apps Scriptの作成・変更・デプロイ
- Googleスプレッドシートの作成・変更
- 外部サービスとの接続
- 試験の実行
- 公開環境への反映
- GitHubへの保存

この試験項目は、実装の許可を意味しない。実装へ進む場合は、悦子さんの別の承認を必要とする。

## 2. 試験の目的

次のことを、先生1人の範囲で確認する。

1. 先生が2行コメントを下書き保存し、安全に確認依頼できる
2. 悦子さんが本文を変更せず、差し戻し・承認・期間管理できる
3. 公開条件を満たす1件だけが一般アプリへ返る
4. 開始前・終了後・取消後・取り下げ後・通信失敗時は通常コメントになる
5. 公開中コメントを残したまま、次の下書きを保持できる
6. 二重保存、古い画面、同時操作、途中失敗からデータを守れる
7. 先生用と管理者用の権限が混ざらない
8. 専用リンクの発行・使用・失効・再発行が設計どおりに動く

## 3. 試験を3段階に分ける

一度にすべてを接続しない。前段階が合格してから次へ進む。

### 第1段階: シートとApps Scriptの保存処理

確認対象:

- 2シートの列と保存単位
- 入力検証
- 状態遷移
- 版管理
- 公開期間の重複防止
- `request_id`と競合防止
- 現在値更新と履歴追記
- 途中失敗時の復旧
- 公開APIの返却内容

この段階では、通常アプリへ接続しない。

### 第2段階: 先生・悦子さんの画面とアクセス管理

確認対象:

- 先生側の入力・確認・差し戻し・結果表示
- 悦子さん側の比較・差し戻し・承認・取消・取り下げ
- 一回限りの入口リンク
- 先生用・管理者用の短期セッション
- 失効・停止・再発行
- 役割と先生IDの分離

この段階でも、通常アプリへ接続しない。

### 第3段階: 一般アプリとの接続

確認対象:

- 公開期間内だけ期間限定コメントを表示
- それ以外は通常コメントを表示
- 通信失敗時の通常コメント
- 終了時刻での自動復帰
- 管理用データを返さないこと
- スマホ実機での2行表示

## 5. 試験データの基本方針

最初は実在する先生名、受付番号、参加者名、対局記録を使用しない。

### 5.1 ダミーの先生

```text
teacher_id: trial-teacher-001
表示名: 試験用先生
```

### 5.2 通常コメント

```text
1行目: 通常コメントの試験用1行目です。
2行目: 通常コメントの試験用2行目です。
```

### 5.3 期間限定コメント

```text
1行目: 8月30日、試験会場でお待ちしています。
2行目: 初めての方も気軽にお声がけください。
```

### 5.4 時刻

試験開始時刻を`T0`とし、次のような相対時刻を使う。

```text
開始前試験: 開始 T0+10分、終了 T0+20分
公開中試験: 開始 T0-10分、終了 T0+10分
終了後試験: 開始 T0-20分、終了 T0-10分
境界試験: 既存終了 T0+10分、次の開始 T0+10分
```

実施時には、日本時間の実際の日時へ置き換えて記録する。

### 5.5 長時間・境界時刻の試験方法

8時間、24時間、正確な開始・終了境界をそのまま待つ試験は、実施方法を先に決める必要がある。

候補は次のいずれかとするが、この文書では決定しない。

- 試験専用環境だけで入口・セッションの期限を短縮する
- サーバー現在時刻を試験用に差し替えられる仕組みを使う
- 境界時刻の直前に試験データを作り、サーバー時刻で確認する

本番用の8時間・24時間という値を、試験の都合で変更したままにしない。採用する方法、試験用設定の識別方法、試験後に本来の値へ戻ったことを確認する手順が決まるまで、該当試験は「保留」とする。

### 7.7 二重保存と競合

| ID | 操作・条件 | 期待結果 |
|---|---|---|
| C-01 | 同じ`request_id`・同じ内容を再送 | `duplicate`を返し、現在値と履歴を増やさない |
| C-02 | 同じ`request_id`を別内容で再利用 | `invalid_request`で拒否し、データを変更しない |
| C-03 | 同じ`request_id`を別操作で再利用 | `invalid_request`で拒否し、データを変更しない |
| C-04 | 古い`version_no`で保存 | `version_conflict`で拒否する |
| C-05 | 同じ画面から保存ボタンを連続操作 | ブラウザーからの送信は1回だけ |
| C-06 | 同時に2つの有効な更新要求を送る | `ScriptLock`により処理が混ざらず、結果が整合する |
| C-07 | 通信結果不明後、同じ要求の結果を照会 | 決定済みの照会方法により、新しい記録を作らず元の`request_id`の結果を確認できる |
| C-08 | 通信失敗・タイムアウトを発生 | 成功表示せず、自動再送しない |

C-07は、結果照会のAPI、画面、返却内容が決定するまで「保留」とする。

### 7.8 現在値と履歴の途中失敗

この試験は、通常の操作ではなく、試験専用の故障条件を設けて行う。

|---|---|---|
| F-01 | 現在値更新後、履歴追記だけを故意に失敗させる | 現在値を更新前へ戻し、`temporary_error`を返す |
| F-02 | F-01後に現在値と履歴を照合 | 中途半端な成功状態が残っていない |
| F-03 | 現在値の復旧も故意に失敗させる | 復旧不能の不整合として記録する |
| F-04 | F-03後に管理者画面を開く | 不整合の警告を表示する |
| F-05 | 不整合が残るコメントを更新 | 追加更新を拒否する |
| F-06 | 決定済みの解消手順を実行 | 現在値と履歴が整合し、警告と更新停止を安全に解除できる |

F-03からF-06は、不整合の記録先・警告方法・解消手順が決定するまで実施保留とする。

## 12. 試験中止条件

次のいずれかが起きた場合は、その段階の試験を止める。

- 通常アプリや本番データが意図せず変更された
- 他の先生または利用者のデータが見えた
- 先生用セッションから管理者操作ができた
- 管理者が先生本文を変更できた
- 公開条件を満たさない本文が一般アプリへ返った
- 通信失敗時に紹介欄が空白になった
- 同じ操作が二重保存された
- 現在値と変更履歴の不整合が残った
- 生のトークンまたはハッシュが履歴・ログ・証拠へ残った
- 失効させた入口またはセッションを再使用できた
- 原因が分からない状態変更が起きた

中止後は新しい操作を重ねず、現在値、履歴、Apps Script実行記録、画面表示を保存してから原因を確認する。

## 13. 合格条件

### 13.1 ダミーデータによる技術試験の合格

ダミーデータによる技術試験の合格には、次のすべてを必要とする。

- 第1段階から第3段階までの必須項目がすべて合格
- 必須項目に「未実施」または「不合格」が残っていない
- 保留項目は、保留理由と実施に必要な決定事項が記録されている
- 不合格項目の原因と再試験結果が記録されている
- 復旧不能の不整合が残っていない
- 入口リンクとセッションを意図どおり失効できる
- 公開期間外と通信失敗時に通常コメントを表示できる
- 公開APIが管理用データを返していない
- 通常アプリと本番データへの予期しない変更がない
- 悦子さんが比較、差し戻し、承認、停止を取り違えず操作できる

U-01～U-08の実施は、この技術試験の合格条件には含めない。

### 13.2 先生本人による試験の完了

先生本人による試験は、技術試験の合格後、悦子さんが別途承認した場合だけ行う。

完了には、次を必要とする。

- 拡張確認のU-01～U-08を実施し、各結果を記録している
- 先生本人が下書き、確認依頼、結果表示を理解できたか記録している
- 迷った操作や分かりにくかった文言がある場合、その内容を記録している
- 先生本人の試験によって通常アプリや本番データへ予期しない変更が起きていない

先生本人による試験が未承認または未実施でも、13.1の技術試験の合格判定とは混同しない。

## 14. 試験終了後の確認

試験終了時に、次を行う。

1. 試験用の入口リンクをすべて失効させる
2. 試験用セッションをすべて失効させる
3. 試験用コメントと履歴の件数を記録する
4. 通常アプリと本番データに予期しない変更がないことを確認する
5. スクリーンショットと返却JSONからトークン類を除く
6. 試験結果を`docs/`とObsidianへ記録する
7. 試験データの保管・削除は、事前に決めた手順と対象一覧に従う
8. デプロイの停止または保管は、悦子さんの確認後に行う
