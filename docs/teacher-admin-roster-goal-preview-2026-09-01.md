## 今回決まったこと

- 参加者ごとに「先生へ名前を表示してよいか」を尋ねる画面は設けない。
- 受付時に、氏名・棋力・置き石・勝敗を**担当の先生だけ**へ表示することを一度案内する。
- 対局名簿を正しい記録の中心にし、参加者アプリは名簿へ情報を届ける方法の一つとする。
- アプリを使わない参加者は、管理者が対局名簿へ追加できる。
- 棋力、置き石、勝敗が後から分かった場合、管理者が訂正できる。
- 基本の手合いと逆コミ目数は別々に保存し、逆コミを受け取る側は黒に固定する。
- 先生は自分の担当分だけを見られ、ほかの先生の氏名・件数・対局内容は受け取れない。
- 住所、電話番号、メールアドレス、受付番号は先生ページへ渡さない。

## 本番の仕組み

```text
参加者アプリ ─┐
               ├─→ 管理者用対局名簿 ─→ 先生専用の取得口 ─→ 担当の先生ページ
管理者の入力 ─┘          │
                         └─ 追加・訂正・記入待ち確認
```

### 対局名簿に持つ最小項目

| 項目 | 用途 | 先生へ表示 |
|---|---|---|
| 対局ID | 行を一意に区別 | しない |
| 対局日・時刻 | 今日の順番を確認 | する |
| 参加者ID | 過去の対局をつなぐ | しない |
| 表示名 | 相手を確認 | する |
| 棋力 | 指導内容の目安 | する |
| 担当先生ID | 表示先をサーバーで限定 | しない |
| 手合い種別 | `sen` または `stones` | 表示文へ反映 |
| 置き石数 | 2、3、4……の数値。先の場合は空 | 表示文へ反映 |
| 逆コミ目数 | 0.5目単位の数値。なしの場合は空 | する |
| 逆コミ受取側 | `black` に固定し、黒が受け取ることを明記 | 表示文へ反映 |
| 勝敗 | 参加者から見た勝ち・負け・持碁を振り返る | する |
| 入力元 | アプリ受付か管理者入力か確認 | 原則しない |
| 更新日時・更新者 | 訂正履歴と事故確認 | しない |

### 先生ごとの閲覧分離

- 先生の入口は、公開の先生紹介ページとは別の専用サイトにする。
- 先生が入口を開いたあと、サーバー側で先生本人を確認して先生IDを確定する。
- 先生ページから送られた先生IDを信用して絞り込む方法にはしない。
- サーバーが、ログイン中の先生IDに一致する行だけを取得して返す。
- 先生Aの入口で先生BのIDやURLを指定しても、先生Bの情報は返さない。
- 入口が無効、期限切れ、本人確認前の場合は、名簿を一件も返さない。

先生の入口をサイトにまとめる利点は、入口URL・案内文・ログイン方法を一か所で管理できることである。ただし、安全性はURLを秘密にするだけでは足りないため、本番ではサーバー側の本人確認と取得制限を必須にする。

### 手合いと逆コミの記録方法

- 基本の手合いは「先、2子局、3子局……」から選ぶ。
- 「追加の逆コミ」は、なし・ありを選ぶ。
- ありの場合だけ、逆コミ目数を入力する。
- 逆コミは黒が受け取るものとして仕様を固定し、画面でも明記する。
- 入力は `3`、`5`、`6.5` などの数値とし、0.5目単位だけを受け付ける。
- 表示時は `3` を「3目」、`6.5` を「6目半」へ変換する。
- 表示例は「先・逆コミ6目半」「2子局・逆コミ3目」「4子局・逆コミ1目半」とする。
- 過去に同じ先生と打った方へ「前回の手合い」を表示する案は、今回の見本へ入れず次段階の候補として残す。

### 見つかった問題と修正

| 問題 | 初めて使う人への影響 | 見本での修正 |

| 最初にすることの順番が弱い | 追加後に何を確認するか迷う | 「1 追加、2 記入待ちを訂正、3 先生ページで確認」を表示 |
