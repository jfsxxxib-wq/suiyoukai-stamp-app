- Every `MANDATORY` item must be `PASS` from immutable, hash-recorded evidence tied to one exact host, guest, VM/config generation, runtime build, session, and checkpoint lineage.
- `NOT PROVEN` means evidence is missing, incomplete, stale, inaccessible, unauthenticated, not bound to the exact subject, or not produced by an authoritative source. It stops the phase without repair, retry, fallback, selection, provisioning, or build.
- `FAIL` means evidence contradicts the requirement, a forbidden channel succeeds, an identity/hash differs, a required control is disabled/inactive, or an unapproved mutation exists. It stops the phase and triggers the fixed rollback/quarantine rule.

- A design value, TOML value, user statement, model summary, or promise not to use an available surface is not runtime evidence.
- Any mandatory `NOT PROVEN` or `FAIL` prevents host adoption and preserves `NB-G4 = NOT PROVEN` and Evidence attempt `0/1`.
