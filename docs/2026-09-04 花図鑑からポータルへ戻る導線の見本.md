# 花図鑑からポータルへ戻る導線の見本

ユーザー要望：花図鑑に本番ポータルへの明示的なボタンを追加し双方向にする。戻る操作で再登録、番号再発行、スタンプ変更を起こさず既存データを保つ。

AGENTSの事前見本確認に従い、outputs/portal-return-preview/index.htmlに隔離した候補を作成。本体・GitHub・本番は未変更。3つの情報タブの下に「← 水曜会ポータルへ戻る」を配置し、地図・図鑑・カード・書庫で利用可能とする。collapsed時にも見えるよう候補側のdock表示を調整。本番ポータルのルートURLへtarget=_selfの通常リンク。個人番号やticket等は付けない。

検証：候補の全scriptタグは本体と一致。リンクに操作用パラメータやonclickなし。既存サーバーをテスト用SQLiteで動かし、同期済み参加者CookieでGETを繰り返しても参加者・花記録番号と全参加者行が不変、Cookie発行と台帳通信が0件であることを確認。ポータルクライアント起動を登録済み・未登録の両方で検証し、GETのみ・POSTなし・localStorage新規作成なし。実データは使用・変更していない。通常の同じブラウザで登録Cookieが残る前提。Cookieが無い場合でも自動再登録はしない。
